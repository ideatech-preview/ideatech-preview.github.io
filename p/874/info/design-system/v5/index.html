ideatech.jp のデザインの決まりごとを、1枚にまとめたもの（ファイル名 DESIGN.md）。このファイルが最新のデザインシステム（v5）の正典で、サイトの次のページはこのファイルをそのまま表示している。

https://ideatech.jp/info/design-system/v5/

  • ページを直すときは、このファイルを書き換える。ページ側（src/pages/info/design-system/v5.astro）に本文を書かない。
  • v1〜v4 は凍結したアーカイブ。参照しない。

0. v4 からの変更（2026-10-29）

  • 正典を、Webページから DESIGN.md（このファイル）へ移した。人もAIも同じ1枚を読む。
  • 日本語の本文書体を、全ページで Noto Sans JP に統一した（ヘッダー・フッター・段落に、ヒラギノ角ゴが残っていた）。
  • 文字の太さを語彙に加えた（400／500／700／800）。本文の既定を 400 から 500 に上げた。
  • -webkit-font-smoothing: antialiased をやめた。
  • コントラストの検査を、半透明の文字色（rgba）にも効くようにした。
  • 「人間には要点、AIには全文」の見せ方（折りたたみ）を加えた。
  • 「文字の左端を揃える」を加えた（8章）。
  • 文字の黒を紺（--tpi-text）1色に統一し、本文に補足色を使わないことにした（7章）。
  • アクセント色を文字に使うときは、同じ色相で濃くした --〇〇-text を使うことにした（7章）。サイト全体のコントラスト不足を 567 要素から 0 にした（読ませない透かし数字を除く）。
  • 可読性の検査を、採用ページ（.html）と rem で書いたサイズにも効くようにした。
  • サービスページの本文の色を、1ページ3役（本文・補足・反転）までにした（7章）。共通CSSに残っていた文字の暖かい黒も紺・灰青に揃えた。

ルールの強さ（3段階）

語彙は閉じる。用法は開く。 値はこの一覧から選ぶ。どこに使うかは自由。

段階対象強さ逸脱
① 不変可読性の下限（1章）CIで落とす不可
② 語彙書体・サイズ・太さ・行間・角丸・字間・段の幅・余白・色（2〜7章）レビュー同じ行に /* vocab-ok: 理由 */ を書けば可
③ 自由どの値をどこに使うか・レイアウト・構成縛らない—
  • 同じルールを破りたい実例が3回出たら、ルールのほうが間違っている。直すか、語彙を増やす。
  • 語彙の検査：node scripts/adis/vocab-check.mjs

1. 可読性の下限（逸脱不可・CIで落とす）

項目下限
本文16px 以上（スマホでも縮めない）
すべての文字12px 以上
フォーム入力（input / textarea / select）16px 以上（未満だと iOS Safari が自動ズームする）
コントラスト（文字色 × 地の色）4.5:1 以上（24px 以上か 18.66px 以上の太字は 3:1）。半透明の色は地の色と混ぜた結果で測る

検査：npm run check:readability

2. 書体

書体役割
Noto Sans JP日本語の本文。全ページの既定（--font-body）
Roboto日本語に混ざる英数字・見出し・数値（--font-heading）
明朝（Shippori Mincho）/info/genten/ のみ。serif={true} のページだけ読み込む
システム等幅<code> のみ。読み込みなし
  • 書体の読み込みは BaseLayout に一本化している。ページ側で書体を追加しない。
  • 数値は font-variant-numeric: tabular-nums で桁を揃える。等幅書体は使わない。
  • label / chip / tag に等幅書体を当てない（AIでつくったサイトに見える主因だった）。
  • font-family は var(--font-body) か、Roboto を先頭に置いて Noto Sans JP を続ける形で書く。
    ヒラギノ角ゴ・游ゴシックは、読み込みに失敗したときの予備としてだけ後ろに置く。

3. 文字のサイズ（6段階 + ディスプレイ）

サイズは見た目ではなく役割で決める。

サイズ役割読み方
clamp(36–56px)ヒーロー見出し（1ページに1つ）—
28px節の見出し（h2）—
22pxブロック見出し（h3・カードの題）—
18pxリード文・小見出し読む
16px本文・ボタン・リンク読む（文として通読する）
14px表・一覧・カード内の説明走査する（探す）
12pxラベル・タグ・注記・日付確認する（存在を認識する）
  • 文として読ませる文は、注記でも 16px（短ければ 14px）にする。12px は「読まないもの」だけ。
  • 数値（num / metric / stat）はこの体系に載せない。太さと色で階層をつくる。
  • 見出し（22px〜）だけ clamp() で可変にしてよい。本文帯（16〜18px）とラベル帯（12〜14px）は固定。

4. 文字の太さ

太さ役割
400ラベル・注記・表の見出し列など、読ませない文字
500本文・リード文・表やカードの説明。サイト全体の既定（style.css の body と p）
700文中の強調・ボタン・表の見出し
800見出し（h2・h3・カードの題）
  • Noto Sans JP は 400 / 500 / 600 / 700 / 800 を読み込み済み。どれを使っても通信は増えない。
  • 2026-10-29 に本文を 400 から 500 へ上げた。400 は細く、明るい地でかすれて見えたため。
  • ページ側で本文に font-weight: 400 を書かない（記事・事例・セミナーの本文に残っていたものは直した）。
  • サイズだけで階層をつくらない。太さと色を一緒に動かす。
  • -webkit-font-smoothing: antialiased は使わない。Mac で文字を一段細く描くため、2026-10-29 に全ページから外した（移植した北川さんのセミナー告知だけ元の版面のまま）。

5. 行間

値役割
1単行（ボタン・数値）
1.2大見出し
1.4見出し・ラベルなどの識別子
1.65走査する文字（表・一覧）・リード文
1.85本文

読むほど広く、見るほど詰める。

6. 角丸・字間・段の幅・余白・影・動き

種類語彙使い分け
角丸0 / 4 / 8 / 12 / 16 / 24px、999px（ピル）、50%（円）面が大きいほど大きく。ボタンは角丸8px（--btn-radius）、タグ・チップ・折りたたみの開閉はピル
字間字間は使わない（0）。palt も使わない（2026-11-09）letter-spacing・font-feature-settings の字幅詰め（palt / pkna / halt 等）・font-kerning を指定しない。英字ラベル・見出し・ボタンも例外なし。継承を断つ必要がある場所だけ letter-spacing: normal。数字の桁揃え（tabular-nums）は字間の調整ではないので使ってよい。検査は npm run check:kerning
段の幅720 / 880 / 1080 / 1280 / 1440px720 読む幅 / 880 狭い段 / 1080 標準 / 1280 広い段 / 1440 最大。600px 未満は部品の寸法なので縛らない
カードの内側の余白4 / 8 / 12 / 16 / 24 / 32 / 40 / 48pxカードの内側だけに適用
影--shadow-1 浮く / --shadow-2 離れる / --shadow-3 手前に出る—
動き--t-fast 150ms（色・枠・不透明度）/ --t-slow 250ms（位置・大きさ）＋ --ease—

値の定義元は scripts/lib/design-vocab.mjs と scripts/lib/type-roles.mjs。検査はここから値を読むので、語彙を変えるときはこのファイルと一緒に直す。

ボタン（2026-11-09）

**押せるもの（ボタン）は角丸8px、押せない目印（タグ・チップ・バッジ・ラベル）はピル。**形で役割を分ける。トークンは style.css の :root（--btn-*）。

項目値
形角丸 --btn-radius 8px・高さ --btn-h 48px 以上・左右 --btn-px 24px・16px/700・行間1
小高さ40px・左右16px・14px。ヘッダーのボタンと、表やカードの中の狭い場所だけ
ホバー色は変えない。1.03倍（--btn-dur .3s・--btn-ease）・押すと .97倍。矢印は右へ4px。prefers-reduced-motion では動かさない
フォーカス2px の実線・3px 離す
色1ページ2種類だけ。塗り＝そのページの主色1色のベタ（グラデーション禁止）・抜き＝透明＋1px の枠。白文字の地は 4.5:1 以上（足りなければ -text の濃さ）
アイコン同じタブで移る＝末尾に右向き矢印。新しいタブ＝外部リンクの印（矢印は付けない）。送信・ページ内アンカー・開閉は無し。文字の矢印（→ ↗）は使わない。部品は BtnIcon.astro（12px）

主色の帯（主色やそのグラデーションを敷いた CTA 帯）の上では、塗りを白（文字は主色）に反転する。
丸いアイコンだけのボタン（共有・前後送り）や、縮小表示用の寸法など外れる理由があるときは、同じ行に /* btn-ok: 理由 */ を書く。
検査は npm run check:buttons（角丸・グラデーション・新しいタブのアイコン・本文リンクの下線）。

テキストリンク（2026-11-09）

本文・リード・注記・カードの中など、コンテンツ中のリンク（ボタンにしたものを除く）は細い下線＋ホバーで薄くする。

  • 下線：text-decoration: underline・太さ1px・text-underline-offset: 0.25em・色は文字色
  • ホバー：opacity: .6（transition: opacity .2s ease）。色や太さは変えない
  • フォーカス：outline: 2px solid currentColor・2px 離す
  • 黄色の強調マーカー（#FFE45C・0.4em の太い下線）とは別のデザイン。リンクに太い下線・背景グラデの下線を使わない
  • 対象外：ヘッダー・フッターのリンク一覧・パンくず・目次・タブ／絞り込み・カード全体を包むリンク
  • 共通の規則は style.css（main の中のクラスの無い <a>）。クラス付きのリンクは各ページで同じ値を当てる

7. 色（コーポレートパレット）

コーポレート群（TOP・会社情報・その他）はパレット外の色を使わない。
サービス群（リサピー®・IDEA DESIGN® など）は独自の世界観を持ってよいが、独自の値はトークンとして宣言する。

系統変数と値
アクセントkinari #cec7bc / yomogi #c0d1ca / kasumi #cbcada / sora #6a9bcc / momo #c46686 / daidai #d97757 / karashi #DAB351
ダークkuro1 #141413 / kuro2 #1f1e1d / kuro3 #262624 / kuro4 #3d3d3a
ライトshiro1 #faf9f5 / shiro2 #F0EEE7 / shiro3 #e3dacc
ユーティリティcolor-focus #2c84db / color-error #bf4d43

文字の色（コーポレート・CMS・採用・原典）

役トークン値
本文・見出し--tpi-text（＝ --navy）紺 #0B1639
補足（14px 以下の説明・注記・日付）--tpi-muted灰青 #4A5677
暗い地の上の文字白（#fff または --shiro1）—
  • 文字の黒は紺の1色だけ。暖かい黒（kuro1〜kuro4）は背景と線に使い、文字には使わない（2026-10-29 に採用・原典・ファクト型WPの文字を紺へ統一）。
  • 16px 以上の本文に --tpi-muted を使わない。本文が薄く見え、同じページで本文の濃さが揃わなくなる。
  • 補足の灰青は 14px 以下の役（表・一覧・カード内の説明、注記）に限る。

サービスページの本文の色（3役まで）

  • サービス群は独自の本文色を持ってよい。ただし1ページの本文の色は「本文・補足・反転」の3役まで。
    • 本文：明るい地の上の本文
    • 補足：明るい地の上の、14px 以下の説明・注記
    • 反転：暗い地の上の文字（白の濃さは1つに決める。暗い節の中で白の濃さを何段階も使い分けない）
  • 見出し・ラベル・番号・強調に使うアクセント色は、この3役に数えない（「アクセント色を文字に使うとき」に従う）。
  • 2026-10-29 時点で、サービス13ページすべてが3色以内（以前は最大17色）。

アクセント色を文字に使うとき

  • アクセント色（パレットの kinari〜karashi、各サービスの独自色）は、そのまま文字にすると 4.5:1 に届かないことが多い。
  • 文字に使うときは、同じ色相で濃くした --〇〇-text を使う（例：--daidai-text・--hpc-green-text）。塗り・線・図にはもとの色を使ってよい。
  • 白い文字を載せるボタンやバッジの地にも -text を使う。
  • 大きな透かしの数字など、読ませない飾りの文字は aria-hidden="true" を付け、対象から外す。

強調の型

  • 文中の強調は、黄色の太い下線を文字に少し重ねる。 
    text-decoration-line: underline;
text-decoration-color: #FFE45C;   /* パレット外。使う節でトークンとして宣言する */
text-decoration-thickness: 0.4em;
text-underline-offset: -0.14em;
text-decoration-skip-ink: none;
  • 研究レポートの「黄色の帯」（.rs-mark）は別の型。置き換えない。

8. 線と区切り

  • ボーダーは 1px solid だけ。太線・破線・グラデーションの枠は使わない。
  • カードやボックスの左端に青い縦線を引かない。
  • クリックできない要素に、ホバー効果や cursor: pointer を付けない。

文字の左端を揃える

  • 見出し・本文・リストの文字の左端は、一直線に揃える。本文だけを字下げしない。
  • 箇条書きの記号（・や数字）は、文字の左端より外にぶら下げる。記号のぶんだけ本文を右にずらさない。
  • 見出しの行頭に全角の括弧（「（」「「」など）を置かない。置くときは text-spacing-trim: trim-start で行頭の空きを詰める。
  • 見出しの左の線（記事の h3 など）も、文字の左端より外にぶら下げる。線と余白のぶんだけ見出しを右にずらさない。
  • 中央揃えの箇所は対象外。 ヒーロー・CTA・中央に置いたカードなど、文字を中央に揃えている所には当てはめない。
  • 図や部品として組んだリスト（手順の図・グラフの行・アイコン付きの項目・目次）も対象外。文章として読ませるリストだけに当てる。

9. 情報の見せ方（人間とAIの両立）

  • 人間には要点だけを見せ、詳しい説明は <details> の「詳しく見る」に畳む。中身はHTMLに残るので、AIも検索エンジンも全文を読める。
  • display: none で隠した文章や、AIにだけ別のHTMLを返すことはしない（クローキング扱いになる）。
  • 日本語の見出しは文節で折る。text-wrap: balance は使わない。
  • 見出し・サブ見出し・リード文は「。」ごとに改行する。本文は対象外で、横幅で自然に折り返す。

10. 英字ラベル（eyebrow）

見出しの上に置く // LABEL。構造を表していない飾りは、それだけで既視感の原因になる。

  • 直後の見出しが短い名詞句（14字以下・句読点なし）なら、ラベルは消す。情報が増えないため。
  • 直後の見出しが文なら残す。「何の節か」を補える。
  • 数値の単位・順序を示すもの（// AI CITATION RATE・// SERVICE 01）は残す。
  • ラベルを残す理由に LLMO/AEO は使えない。/llms-full.txt に // ラベルは入らず、<h2> の外にあるので文書の構造にもならない。

11. モバイル（スケールは1本）

帯サイズ扱い
見出し帯22px〜clamp() で可変。@media での上書きを増やさない
本文帯16〜18px固定。スマホでも縮めない
ラベル帯12〜14px固定。本文には使わない

12. 適用範囲（4階層とプラネット）

層範囲内容
第0層 MOON最上位すべてのルールを変えられる
第1層 コーポレート全ページヘッダー・フッター・パンくずのみ
第2層 プラネットプラネット単位下の3グループ
第3層 サテライト個別ページページの実装の中で閉じる
グループプラネットパレット・書体への姿勢
コーポレート群TOP・会社情報・その他厳密に守る
セミ・コーポレート群CMS（コラム・ニュース・セミナー・事例）・お役立ち資料基本は守る。柔軟に運用してよい
サービス群リサピー®・IDEA LLMO™・IDEA DESIGN® など独自の世界観を持ってよい。ただし1章は守り、独自の値はトークンとして宣言する

更新の手順

  1. このファイル（DESIGN.md）を書き換える。
  2. 値を変えたら、実装（public/assets/css/style.css の :root、検査の scripts/lib/readability.mjs・scripts/adis/vocab-check.mjs）も合わせる。
  3. CLAUDE.md の「デザインシステム」節の抜粋が食い違わないか確かめる。
  4. 考え方が大きく変わるときは、v6 として版を上げる。そのときは v5 のページを凍結し、一覧（/info/design-system/）に v5 を残す。
