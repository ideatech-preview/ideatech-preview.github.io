0. v5 からの変更（2026-11-09）

文字の色と強弱

  • **文字色を2色だけにした。**明るい地の上は黒 #1d1d1f（--text-black）、暗い地・色の塗りの上は白 #ffffff（--text-white）。紺 --tpi-text・暖かい黒 kuro・灰青 --tpi-muted・各色の --〇〇-text は、文字色としては廃止した（7章）。
  • 透過で文字を薄めない。color に rgba / hsla / 8桁の hex を使わない。文字を薄く見せるための opacity も使わない。
  • **アクセント色の文字・グラデーションの文字（background-clip: text）を使わない。**見出しの強調語・数値・ラベル・リンク・タグの文字も白か黒。色はアイコン・線・枠・塗りにだけ使う。
  • **強弱は文字の大きさと太さでつける。**色・透過・グラデーションで濃淡や強調をつけない。
  • 本文の太さを 500 から 400 に戻した（4章）。読む・走査する・確認する文字は 400、見出し・強調・ボタン・ラベルは 700 / 800。本文を細く、強調を太くして差を出す。
  • マーカー（黄色の太い下線）を引く文字は太字（700）にした（7章）。
  • 検査 npm run check:text-color を CI に加えた。2色以外の文字色・透過・グラデーションの文字を落とす。

ボタン・テキストリンク・字間（#818・6章）

  • ボタンは角丸 8px（--btn-radius）・高さ 48px・16px/700。押せない目印（タグ・チップ）はピルのまま。
  • ボタンの色は1ページ「塗り（主色1色・グラデーション禁止）」と「抜き（透明＋1px の枠）」の2種類だけ。ホバーは色を変えず 1.03 倍。アイコンは同じタブ＝右向き矢印、新しいタブ＝外部リンクの印。
  • テキストリンクは細い下線（1px・0.25em・文字色）＋ホバーで opacity: .6。
  • 字間は使わない（0）。letter-spacing・palt などの字幅詰め・font-kerning を指定しない。
  • 検査 npm run check:buttons・npm run check:kerning。

英字ラベル・段の幅・節の並び（2026-11-10）

  • 英字ラベル（// LABEL・BEFORE/AFTER・PHASE 01 など）は使わない（10章）。v5 までの「見出しが文なら残す」「順序を示すものは残す」は廃止した。
  • **段の幅の標準は 1080px。**TOP は FV を除いて全節を 1080px にそろえた（6章）。
  • 明るい地の節が続くときは、白と淡い色を交互に敷く（9章）。サービスページの量と並びの決まりは docs/service-page-rules.md。

白・NEW の赤・グラデーションの帯（2026-11-11）

  • shiro1 を完全な白 #ffffff にした（旧 #faf9f5）。--white もこれを指す。
  • NEW バッジの赤を --color-error #BF4D43 にした（旧 #E53935 は白い文字と 4.2:1 で、1章の 4.5:1 を割っていた）。
  • 白い文字を載せるグラデーションの帯をやめ、1色にした（レポピー®の CTA・ハクピー®のピラミッドと料金・IDEA AI™ の料金）。明るい側で白い文字が 4.5:1 を割っていたため。

ルールの強さ（3段階）

語彙は閉じる。用法は開く。 値はこの一覧から選ぶ。どこに使うかは自由。

段階対象強さ逸脱
① 不変可読性の下限（1章）・文字の色は白と黒の2色（7章）CIで落とす不可（文字色は理由を書いた行だけ可）
② 語彙書体・サイズ・太さ・行間・角丸・字間・段の幅・余白・塗りと線の色（2〜7章）レビュー同じ行に /* vocab-ok: 理由 */ を書けば可
③ 自由どの値をどこに使うか・レイアウト・構成縛らない—
  • 同じルールを破りたい実例が3回出たら、ルールのほうが間違っている。直すか、語彙を増やす。
  • 語彙の検査：node scripts/adis/vocab-check.mjs

1. 可読性の下限（逸脱不可・CIで落とす）

項目下限
本文16px 以上（スマホでも縮めない）
すべての文字12px 以上
フォーム入力（input / textarea / select）16px 以上（未満だと iOS Safari が自動ズームする）
コントラスト（文字色 × 地の色）4.5:1 以上（24px 以上か 18.66px 以上の太字は 3:1）。文字色は白か黒なので、地の色で決まる。色の塗りの上は、白と黒のうち 4.5:1 以上になるほう

検査：npm run check:readability

2. 書体

書体役割
Noto Sans JP日本語の本文。全ページの既定（--font-body）
Roboto日本語に混ざる英数字・見出し・数値（--font-heading）
明朝（Shippori Mincho）/info/genten/ のみ。serif={true} のページだけ読み込む
システム等幅<code> のみ。読み込みなし。使う所：コードの例・TOP の FV の図形ラベル・ページ下の版数と最終更新日の帯（2026-11-11）
  • 書体の読み込みは BaseLayout に一本化している。ページ側で書体を追加しない。
  • 数値は font-variant-numeric: tabular-nums で桁を揃える。等幅書体は使わない。
  • label / chip / tag に等幅書体を当てない（AIでつくったサイトに見える主因だった）。
  • font-family は var(--font-body) か、Roboto を先頭に置いて Noto Sans JP を続ける形で書く。
    ヒラギノ角ゴ・游ゴシックは、読み込みに失敗したときの予備としてだけ後ろに置く。

3. 文字のサイズ（6段階 + ディスプレイ）

サイズは見た目ではなく役割で決める。

サイズ役割読み方
clamp(36–56px)ヒーロー見出し（1ページに1つ）—
28px節の見出し（h2）—
22pxブロック見出し（h3・カードの題）—
18pxリード文・小見出し読む
16px本文・ボタン・リンク読む（文として通読する）
14px表・一覧・カード内の説明走査する（探す）
12pxラベル・タグ・注記・日付確認する（存在を認識する）
  • 文として読ませる文は、注記でも 16px（短ければ 14px）にする。12px は「読まないもの」だけ。
  • 数値（num / metric / stat）はこの体系に載せない。太さで階層をつくる（色は使わない）。
  • 見出し（22px〜）だけ clamp() で可変にしてよい。本文帯（16〜18px）とラベル帯（12〜14px）は固定。

4. 文字の太さ

太さ役割
400本文・リード文・説明文・注記・表のセル・リストなど、読む・走査する・確認する文字。サイト全体の既定（style.css の body と p）
500ナビゲーション（ヘッダー・フッターのリンク一覧）など、操作の部品の文字
700文中の強調（strong・マーカー）・ボタン・表の見出し・ラベル
800見出し（h2・h3・カードの題）
  • Noto Sans JP・Roboto は 100 / 200 / 400 / 500 / 600 / 700 / 800（Roboto は 900 も）を読み込み済み。文字データは使うページでしか取りに行かないので、使わないページの通信は増えない。
  • TOP（/）だけの例外（2026-11-10）：FV の見出しは 700（2026-11-11 に 100 から変更・句点なし）、節の見出し（h2）は 200、連載名は 400。ほかのページの見出しは 800 のまま（広げるかは未定）。
  • 2026-11-09（v6）に本文を 500 から 400 へ戻した。文字の色を黒 #1d1d1f の1色にし、強弱を大きさと太さでつけることにしたため。本文が細いほど、見出しと強調の太さが効く。
  • ページ側で本文に font-weight: 500 を書かない。
  • サイズだけで階層をつくらない。太さを一緒に動かす（色では動かさない）。
  • -webkit-font-smoothing: antialiased は使わない。Mac で文字を一段細く描くため、2026-10-29 に全ページから外した（移植した北川さんのセミナー告知だけ元の版面のまま）。

ボタン（2026-11-09）

**押せるもの（ボタン）は角丸8px、押せない目印（タグ・チップ・バッジ・ラベル）はピル。**形で役割を分ける。トークンは style.css の :root（--btn-*）。

項目値
形角丸 --btn-radius 8px・高さ --btn-h 48px 以上・左右 --btn-px 24px・16px/700・行間1
小高さ40px・左右16px・14px。ヘッダーのボタンと、表やカードの中の狭い場所だけ
ホバー色は変えない。1.03倍（--btn-dur .3s・--btn-ease）・押すと .97倍。矢印は右へ4px。prefers-reduced-motion では動かさない
フォーカス2px の実線・3px 離す
色1ページ2種類だけ。塗り＝そのページの主色1色のベタ（グラデーション禁止）・抜き＝透明＋1px の枠。白文字の地は 4.5:1 以上（足りなければ -text の濃さ）
アイコン同じタブで移る＝末尾に右向き矢印。新しいタブ＝外部リンクの印（矢印は付けない）。送信・ページ内アンカー・開閉は無し。文字の矢印（→ ↗）は使わない。部品は BtnIcon.astro（12px）

主色の帯（主色やそのグラデーションを敷いた CTA 帯）の上では、塗りを白（文字は主色）に反転する。
丸いアイコンだけのボタン（共有・前後送り）や、縮小表示用の寸法など外れる理由があるときは、同じ行に /* btn-ok: 理由 */ を書く。
検査は npm run check:buttons（角丸・グラデーション・新しいタブのアイコン・本文リンクの下線）。

テキストリンク（2026-11-09）

本文・リード・注記・カードの中など、コンテンツ中のリンク（ボタンにしたものを除く）は細い下線＋ホバーで薄くする。

  • 下線：text-decoration: underline・太さ1px・text-underline-offset: 0.25em・色は文字色
  • ホバー：opacity: .6（transition: opacity .2s ease）。色や太さは変えない
  • フォーカス：outline: 2px solid currentColor・2px 離す
  • 黄色の強調マーカー（#FFE45C・0.4em の太い下線）とは別のデザイン。リンクに太い下線・背景グラデの下線を使わない
  • 対象外：ヘッダー・フッターのリンク一覧・パンくず・目次・タブ／絞り込み・カード全体を包むリンク
  • 共通の規則は style.css（main の中のクラスの無い <a>）。クラス付きのリンクは各ページで同じ値を当てる

7. 色

文字の色は白と黒の2色だけ（全ページ・CIで検査）

地文字の色トークン
明るい地（白・shiro・ミスト・淡い色の面）黒 #1d1d1f--text-black
暗い地・色の塗り（ボタン・チップ・バッジの地・帯）白 #ffffff--text-white
  • トークンは style.css の :root。文字色はこの2つ（または inherit / currentColor）だけで書く。
  • 色の塗りの上の文字は、白か黒のうちコントラスト 4.5:1 以上になるほう。
  • 透過で文字を薄めない。color に rgba / hsla / 8桁の hex を使わない。文字を薄く見せるための opacity も使わない（テキストリンクのホバーの opacity: .6 は操作の反応なのでよい。アニメーション中の一時的な opacity もよい）。
  • **アクセント色の文字・グラデーションの文字（background-clip: text）を使わない。**見出しの強調語・数値・ラベル・リンク・タグの文字も白か黒。
  • **色はアイコン・線・枠・塗り（ボタン・チップの地・グラフ）にだけ使う。**SVG の <text> も文字なので白か黒。グラフの系列の色・アイコンの fill / stroke は対象外。
  • **強弱は大きさ（3章）と太さ（4章）でつける。**補足・注記は小さく（14px / 12px）・細く（400）、強調・見出しは太く（700 / 800）。色の代わりにサイズを 12px 未満へ下げない（1章）。
  • 紺 --tpi-text・暖かい黒 kuro1〜4・灰青 --tpi-muted / --tpi-soft・各色の --〇〇-text は、文字色としては使わない（v6 で廃止）。kuro / shiro は背景と線に、--〇〇-text は白い文字を載せる塗りの地に使ってよい。
  • 読ませない飾りの文字（大きな透かしの数字など）は aria-hidden="true" を付ける。
  • 外れてよい理由があるとき（アイコンの線の色を color で渡す currentColor の部品など）は、同じ行に /* text-color-ok: 理由 */ を書く。
  • 検査：npm run check:text-color

例外（この3つだけ）

  • IDEA DESIGN® の FV で切り替わる文字（青→紫のグラデーション）。
  • Octy™ の4機能名（Octy™ Core / Octy™ Maintenance / Octy™ Report / Octy™ Command）のグラデーション（同じ青→紫）。
  • TOP の「IDEA, TECHNOLOGY and HUMAN.」の流れる文字（2026-11-11・aria-hidden の飾り）。上段は青系の線（#b9cbe8）、下段は薄いグレーの塗り（#e4e4e7）。

パレット（塗り・線・図の色）

コーポレート群（TOP・会社情報・その他）はパレット外の色を使わない。
サービス群（リサピー®・IDEA DESIGN® など）は独自の世界観を持ってよいが、独自の値はトークンとして宣言する。どちらも文字の色は白と黒だけ。

®・™マーク（2026-11-11）

  • 本文・見出しの®と™（Octy™ など）は、文字の半分の大きさで右上の1つの形にそろえる（sup.reg・style.css）。
  • HTML は src/middleware.ts が書き出し時に <sup class="reg">®</sup> で包む（™ も同じクラス）ので、ページでは「リサピー®」「Octy™」とふつうに書けばよい。手で包むときも sup.reg を使い、ページごとに別のクラスや大きさを作らない。
  • <head>（題名・説明文・構造化データ）と AI 向けの文字データは、ふつうの「®」のまま（文字だけの欄のため）。®（異体字セレクタ付き）は使わない。
  • サービス名には、本文のすべての出現に ® か ™ を付ける（2026-11-11）。登録商標＝® はリサピー®・レポピー®・ハクピー®・コラピー®・X-Questions®・コンテンツセールス®・IDEA DESIGN®・ルールメイクリサーチ®・IDEAリスキリング®、それ以外＝™ は IDEA LLMO™・IDEA LLMO BOARD™・IDEA AI™・PR-GROWTH™・Octy™。src/middleware.ts が書き出し時に足すので、Notion の記事本文も含めて素で書いてよい（名前の一覧は middleware の MARKS）。

強調の型

  • 文中の強調は、黄色の太い下線を文字に少し重ね、**文字は太字（700）**にする。 
    font-weight: 700;
text-decoration-line: underline;
text-decoration-color: #FFE45C;   /* パレット外。使う節でトークンとして宣言する */
text-decoration-thickness: 0.4em;
text-underline-offset: -0.14em;
text-decoration-skip-ink: none;
  • 強調に文字の色を使わない（下線の黄色は線の色なのでよい）。
  • 研究レポートの「黄色の帯」（.rs-mark）は別の型。置き換えない。

8. 線と区切り

  • ボーダーは 1px solid だけ。太線・破線・グラデーションの枠は使わない。
  • 本文の中の箱は「汎用の箱」1種類だけにする（2026-11-11）。白か淡いグレー（#f6f6f7）の面・1px の細い枠（rgba(20,20,19,.10)）・角丸 16px・内側 32px（スマホ 24px）。面の色は節の地の逆にする（灰の節＝白い箱、白い節＝淡いグレーの箱）。
    • 箱と箱は 16px あけて並べる。区切り線だけで仕切った帯、くっつけた帯、三角の矢印でつないだ帯は使わない。順序は番号（01・02…）で示す。
    • 影・色の線・角ごとに違う丸みは付けない。ヒーローの画面の見本など「絵」として描いたものは対象外。
    • ページを直すときは、1つの箱だけでなく、そのページの箱をすべて洗い出してまとめてそろえる。
  • カードや箱の上端・左端に、色の線（太い枠・帯・グラデーションの線）を引かない（2026-11-11 に全ページから外した）。色で区別したいときは、線ではなく中の文字やアイコンで示す。記事の見出しの左の線と、引用の線は箱ではないので対象外。
  • クリックできない要素に、ホバー効果や cursor: pointer を付けない。

文字の左端を揃える

  • 見出し・本文・リストの文字の左端は、一直線に揃える。本文だけを字下げしない。
  • 箇条書きの記号（・や数字）は、文字の左端より外にぶら下げる。記号のぶんだけ本文を右にずらさない。
  • 見出しの行頭に全角の括弧（「（」「「」など）を置かない。置くときは text-spacing-trim: trim-start で行頭の空きを詰める。
  • 見出しの左の線（記事の h3 など）も、文字の左端より外にぶら下げる。線と余白のぶんだけ見出しを右にずらさない。
  • 中央揃えの箇所は対象外。 ヒーロー・CTA・中央に置いたカードなど、文字を中央に揃えている所には当てはめない。
  • 図や部品として組んだリスト（手順の図・グラフの行・アイコン付きの項目・目次）も対象外。文章として読ませるリストだけに当てる。

9. 情報の見せ方（人間とAIの両立）

  • 人間には要点だけを見せ、詳しい説明は <details> の「詳しく見る」に畳む。中身はHTMLに残るので、AIも検索エンジンも全文を読める。
  • display: none で隠した文章や、AIにだけ別のHTMLを返すことはしない（クローキング扱いになる）。
  • 日本語の見出しは文節で折る。text-wrap: balance は使わない。
  • 見出し・サブ見出し・リード文は「。」ごとに改行する。本文は対象外で、横幅で自然に折り返す。
  • 明るい地の節が続くときは、白と淡い色（ミスト・shiro2 など）を交互に敷き、節の切れ目を見せる。
  • 詳細は下層ページへ送る。TOP やサービスページには「検討に要る情報」だけを置き、要点の下に「詳しく見る」のリンクを付ける。
  • サービスページの量・節の並び・節の余白（--section-y: clamp(80px, 10vw, 136px)）は docs/service-page-rules.md に従う。

10. 英字ラベル（eyebrow）

**英字ラベルは使わない（2026-11-10・全ページ）。**見出しの上の // LABEL、BEFORE / AFTER、PHASE 01、SERVICE 01 などの英字の飾りを置かない。

  • 情報が増えない。見出しの英訳か言い換えにしかならず、既視感（AIでつくったサイトに見える）の原因になる。
  • AI対策にもならない。/llms-full.txt に入らず、<h2> の外にあるので文書の構造にもならない。
  • 順序や区分を示したいときは、日本語の見出しや数字（01・02）で書く。
  • 対象外：ロゴ・商品名・固有名詞（Octy™ Core など）、英語のページ。
  • 例外：一覧ページのヒーロー（ListHero・2026-11-11）の英語の大きな表題（Case Studies・Research など。Roboto 200）。見出しのラベルではなくヒーローの絵として置き、aria-hidden。h1 は日本語で、その下に補足の大きさで添える。
